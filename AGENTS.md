# Working on xorio.rs

Instructions for coding agents (Claude Code reads this through `CLAUDE.md`). `README.md` has the full layout.

## The one rule

**Edit sources in `src/` (and static files in `project/`). Never edit generated output.**

The site is built by `build.js` into `dist/`, which is gitignored. There is no `index.html`, `about.html`, `p/` or `f/` in the repository; those exist only in `dist/` after a build and are overwritten on the next one. Generated files start with a `Generated by build.js` banner — if you see it, you are in the wrong file.

| To change | Edit |
|---|---|
| Projects, groups, filters, experiments, contacts, About/Grow/Friends copy | `src/data.js`, and page markup in `src/render.js` |
| Nav, footer, `<head>` | `src/shell.html` |
| Styles | `src/styles.css` |
| Browser behaviour (filters, terminal, theme, GitHub cards) | `src/app.js`, `src/theme.js` |
| Privacy policy | `src/privacy.html` |
| Screenshots | `src/shots/<id>.png`, then `npm install && npm run images` and commit the new `project/assets/img/` files |
| Headers, CSP, redirects, build settings | `vercel.json` |

## Preview locally

```sh
npm run dev      # build, serve dist/ on http://localhost:8000, rebuild + reload on save
```

It serves the same clean URLs (`/p/<id>`, `/f/<key>`, `/about`), headers and CSP as production, so a CSP violation shows up locally. `PORT=8001 npm run dev` if 8000 is taken. For a one-off check: `node build.js` (must exit 0) and `npm run serve`.

## Before committing

1. `node build.js` exits 0.
2. Check the pages you touched in the browser (both themes if you changed styles) with no console errors.
3. Commit only sources — never `dist/`.

## Deploying

Pushing to `main` deploys to https://xorio.rs automatically: Vercel runs `node build.js` and serves `dist/`. The site owner is fine with committing directly to `main` for content changes; use a pull request for structural changes (build, routing, CSP). Every push and PR also runs the `Build site` workflow, which fails if the build breaks.

## Constraints

- The CSP (`vercel.json`) allows no inline scripts or styles: no `style="…"` attributes or `<script>` blocks in pages. Style dynamic values through CSSOM (`el.style.x = …`) or classes.
- New external hosts (images, APIs) must be added to the CSP, and to the third-party list in `src/privacy.html`.
- Keep counts in prose approximate (`approx()` in `src/render.js`), so copy does not go stale as projects are added.
- `build.js` has no dependencies; keep it that way (Vercel skips `npm install`). Only `tools/images.js` needs `sharp`.
